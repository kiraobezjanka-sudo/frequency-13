# Частота 13: Последний эфир

## Концепция и рамки

Оригинальная одностраничная сюжетная браузерная игра на русском языке. Игрок попеременно выбирает реплики инженера Лады и курьера Севера, чтобы запустить маяк до прихода прилива. Игра работает статически, без сервера, библиотек и сетевых запросов.

## Правила, которые нельзя ломать

- Состояния игры: `idle`, `intro`, `running`, `paused`, `finished`.
- Перед первым диалогом всегда показываются три коротких кадра предыстории; только после них разрешены сюжетные выборы.
- Каждый показанный выбор ведёт к существующей следующей сцене или одной из четырёх концовок.
- На концовки влияют доверие, сигнал, время, катушка и признание Севера.
- Перезапуск полностью сбрасывает маршрут, показатели и найденные предметы.
- Пауза блокирует сюжетные выборы, но оставляет доступными продолжение и перезапуск.

## Управление и доступность

- Мышь/сенсор: экранные кнопки и варианты реплик.
- Клавиатура: `1`–`3` выбрать реплику, `Space` начать/листать предысторию/продолжить, `Escape` пауза, `R` перезапуск.
- Интерактивные элементы имеют видимый фокус; интерфейс работает на узких экранах и учитывает `prefers-reduced-motion`.

## Технологии и структура

- `index.html` — семантическая разметка.
- `styles.css` — адаптивный визуальный слой и CSS-иллюстрации персонажей.
- `game-core.js` — авторитетная модель, диалоговое дерево и расчёт концовок.
- `game.js` — DOM-рендеринг и единые семантические действия для клавиатуры/указателя.
- `tests/game-core.test.mjs` — детерминированные проверки маршрутов и состояний.

## Проверка

- `npm test` — тесты модели.
- `npm run check` — синтаксическая проверка JavaScript.
- `npm run build` — статическая сборка в `dist/`.
- В браузере проверить старт, варианты `1`–`3`, паузу/продолжение, все концовки, перезапуск, ширины desktop/mobile и отсутствие ошибок в консоли.

## Git и публикация

- Игровые изменения создаются в ветках `codex/*`; текущая задача — `codex/frequency-13`.
- Коммит, удалённый репозиторий, Pull Request и публикация требуют отдельного одобрения пользователя.
- Если будет настроено PR-превью, оно должно быть отдельным для каждого PR и собираться из `dist/`.
- PR-превью публикуется из `dist/` в `gh-pages/pr-preview/pr-<номер>/`, обновляется при новых коммитах и удаляет только собственную папку после закрытия PR.
- После явного слияния в `main` production-сборка публикуется в корень `gh-pages`, не удаляя активные PR-превью.
